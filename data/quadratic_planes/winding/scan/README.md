# Theorem W certificates for the planes over `ℚ(√d)`, `d ≡ 11 (mod 12)`

Each file `cert_<d>_<D>.json.gz` is an exact certificate that no character of the group generated by a set `U` of
unit vectors `((a + b√d)/D, (c + e√d)/D)` maps every vector of `U` into `[1/3, 2/3]`. By Theorem W
(`notes/winding_lemma.md`), `Cay(ℤU, U)` is then not 3-colourable, so `χ(ℚ(√d)²) ≥ 4`.

This directory has one certificate for each of the 155 squarefree `d ≡ 11 (mod 12)` below 2000, the smallest file
any run found for that `d`. Between 2000 and 10 000, 593 of the 611 squarefree `d ≡ 11 (mod 12)` have a certificate;
those files stay on the branches of the machines that wrote them, listed in `beyond2000.tsv` (below).

**What this adds.** Theorem 1 of `notes/four_colours_11_mod_12.md` proves `χ(ℚ(√d)²) ≥ 4` for every
`d ≡ 11 (mod 12)`, by hand and in Lean (`lean/FourColours.lean`). The certificates here do not use that proof: each
one settles one field by a finite computation checked in exact arithmetic, through Theorem W alone. So they check
Theorem 1 field by field, independently of its proof.

Check one with

```sh
python3 ../check_w.py cert_<d>_<D>.json.gz         # prints VERIFIED: ...
python3 ../check_w_indep.py cert_<d>_<D>.json.gz   # the second checker, written separately
```

Both checkers use integers and fractions only. `check_w.py` checks that every vector has length 1, that every
relation holds, that every branch of the tree covers every integer value in its range, and that every leaf's Farkas
vector is valid. `check_w_indep.py` checks the same from the certificate format alone, and reports the rank of the
vectors, whether the relations generate all integer relations among them, and whether `U` is the set of all unit
vectors with denominator `D` (none of the three is needed for the conclusion). Both accept all 155 certificates
here (`checks.txt`, one line from each checker per file).

**How the sets `U` were found.** The searches are floating-point guides; only the certificates are proofs.
- `../scan_all.py`: for each `d`, the denominators `D ≤ 2400` with `6 | D` and 24 to 110 unit vectors (up to sign),
  ranked by that number; the relation-space test (`../kapparel.py`) on the twelve richest; the first infeasible one
  is certified.
- `../single_scan.py`: every `D ≤ 6000` with `6 | D` and at least 24 vectors, fewest vectors first, until one is
  infeasible.
- `../union_search.py` and `../union_cert.py`: the union of the unit vectors of several denominators (single ones,
  pairs and triples of the richest), written over their least common multiple. A union has relations between
  vectors of different denominators that no single denominator has.
- `../certify_w2.py` writes the certificate: branch and bound over the integer values of the relations, with a
  rational Farkas vector at every leaf.

## Between 2000 and 10 000

Two machines ran the same search (`single_scan.py`, then `union_search.py` with the twelve richest denominators, and
`union_cert.py`) over all 611 squarefree `d ≡ 11 (mod 12)` with `2000 < d < 10 000`. They certified 593 of them: 509
with a single denominator `D ≤ 6000` and 84 with a union. For the other 18 the floating-point search found no
infeasible set; that says nothing about these fields, which Theorem 1 covers:
`4787, 5507, 5843, 6827, 7235, 7283, 7451, 7883, 8123, 8363, 8387, 8627, 8747, 8843, 8903, 9203, 9323, 9587`.

The certificates (327 MB in all) are not copied here. 591 of them are on the branches `claude/winding-share-z1` and
`claude/winding-share-z2` of this repository, under `data/quadratic_planes/winding_share_z1/hardcerts/` and
`.../winding_share_z2/hardcerts/`; `beyond2000.tsv` gives, for each of the 611 values, `D`, the number of vectors,
relations, nodes and leaves, the branch and path of the file, its git blob id and sha256, and the verdicts of the two
checkers, which both accept all 591. To check one:

```sh
b=claude/winding-share-z1; f=data/quadratic_planes/winding_share_z1/hardcerts/cert_2003_4134.json.gz
git fetch origin $b && git show origin/$b:$f > c.json.gz
sha256sum c.json.gz && python3 ../check_w.py c.json.gz     # compare with the row of d = 2003
```

The two others were checked once, by `check_w.py` on the machine that wrote them, and not kept, as each is over
the 50 MB that those machines allowed for a committed file (GitHub warns above 50 MB and refuses files above 100 MB):
`d = 5207` (`D = 3996`, 34 vectors, 4 165 215 nodes, 113 MB) and `d = 7763` (`D = 1 062 270`, the union of `D = 3330`
and `5742`, 66 vectors, 1 029 909 nodes, 92 MB). In `beyond2000.tsv` they have no path.

The difficulty follows the two cases of Theorem 1. Of the 306 values `d ≡ 23 (mod 24)`, 304 have a certificate with
a single denominator; of the 305 values `d ≡ 11 (mod 24)`, 205 do, 83 needed a union and 17 have none.
